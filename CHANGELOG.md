# Что нового в Sculptor

Версия показывается в шапке сайта, рядом с логотипом. Задаётся она в
одном месте — `config/__init__.py`.

Нумерация семантическая: `MAJOR.MINOR.PATCH`. До 1.0 новые возможности
поднимают MINOR, исправления — PATCH. Изменения, требующие действий при
обновлении (переезды схемы базы, новые файлы, которые нужно положить руками),
отмечены в каждой версии разделом **«Обновление»** — его стоит читать до
того, как запускать новый код.

## 0.4.33

### Изменено

- Вычитка текстов, продолжение: снимки плат подписаны «Вид сверху» /
  «Вид снизу» (вместо Top side / Bottom side), «Ссылка на трекер»;
  заголовки таблицы состава в разделе «Серверы» — с заглавной; «вручную»
  вместо «руками»; «Параметры скопированы» вместо «списаны»; «совпадения»
  вместо оборванного «совпадает с»; дата утверждения ревизии — в формате
  дд.мм.гггг; состояния рендера картинки — в одном роде («готова», «не
  удалась»); ссылка «Удалить позицию» в форме позиции.

Две новые миграции (`boards.0018`, `components.0021`) меняют только
подписи полей и состояний — таблицы не трогают. В Docker применяются сами
при старте.

### Обновление

Миграция `components.0019` переименовывает таблицы (`ALTER TABLE … RENAME`,
одной транзакцией) и в Docker применяется сама при старте. Поэтому:

1. Снимите свежую резервную копию базы (docs/deploy.md, раздел про
   резервные копии).
2. `git pull` и `docker compose up -d --build`.
3. Проверьте, что последней стоит `[X] 0019_rename_oy_tables`:
   `docker compose exec web python manage.py showmigrations components`.

Если что-то читает эти таблицы напрямую, минуя сайт (отчёты, скрипты,
сторонний софт), — поменяйте в нём имена. Подробности и откат —
docs/schema-history.md, «Таблицы Django: oy_ → components_».

- **Vendor в форме компонента — выпадающий список, у каждой группы

добавляет значения в справочник, записи компонентов не трогает; повторный
запуск ничего не дублирует):
`docker compose exec web python manage.py load_options --field vendor --per-group`.

## 0.4.8

### Добавлено

- **Подсказки для строк BOM без связи.** Над составом ревизии — кнопка
  «Подобрать для N строк»: строки, не связавшиеся с библиотекой, и похожие
  на них записи — тот же артикул у иначе записанного производителя
  («TI» и «Texas Instruments»), другие разделители, суффикс упаковки.
  Рядом — производитель и описание записи. Кнопка «Связать» ставит связь,
  не меняя значений строки; в админке такая связь подписана
  «подтверждён по подсказке», и `relink_boards` её не трогает.
- **Поиск дублей: проверка «Артикул записан по-разному».** Находит записи,
  у которых Vendor PN совпадает, если не считать разделителей
  («2N7002K-7» и «2N7002K7»), или отличается суффиксом после разделителя
  («MMBT3904» и «MMBT3904-7-F»).

### Изменено

- **Предположения при импорте ссылок находят больше.** Опечатка в начале
  артикула теперь находится (раньше — никогда), похожий артикул ищется по
  всей библиотеке, а не среди номеров с тем же началом. Если артикул
  нашёлся по нескольким кускам названия задачи, выше встаёт лучшее
  совпадение, а не первое найденное — раньше верная запись могла уступить
  соседнему номиналу.
- **Отечественные артикулы больше не склеиваются.** Запятая и кириллица
  теперь часть артикула: «5,1 кОм» и «51 кОм», «1,1 Ом» и «1,1 кОм» —
  разные записи, а не «отличаются только разделителями».
- Причина предположения «в задаче лишний суффикс» называется
  «в библиотеке без суффикса».

### Обновление

Новая зависимость — `rapidfuzz`. На сервере: `docker compose up -d --build`
(образ поставит её сам). Локально:
`venv\Scripts\python.exe -m pip install -r requirements-dev.txt`.
SQL и миграций нет.

  библиотекой — только для чтения; новые строки добавляются на сайте, из

### Обновление

Порядок важен: сначала база, потом код. В Docker `migrate` запускается при
каждом старте, поэтому остановите приложение до первого шага.

1. Резервная копия базы и медиа (`docs/deploy.md`).
2. Если обновляетесь со сборки, где проект ещё назывался `oy_system`:
   `sql/rename_to_sculptor.sql` и переименование базы —
   `docs/schema-history.md`, раздел «Переименование проекта».
3. Если приложение составов ещё называлось `products`:
   `sql/rename_products_app.sql`.
4. Переезд на свою модель пользователя: `sql/move_user_to_users.sql`.
5. В `.env`: `POSTGRES_DB=sculptor_db`, `POSTGRES_SCHEMA=sculptor,public`.
6. Положить `components/static/components/htmx.min.js` версии 2.0.10
   (`docs/install.md`, раздел «HTMX»). Без него сайт работает обычными
   переходами.
7. Для рендера STEP в Docker — `WITH_STEP=true` в `.env` и сборка образа.
8. Запуск: `migrate` накатит новые миграции сам. Проверка —
   `manage.py check_schema`, `manage.py check_step_render --render`,
   `manage.py test`.

Каждый SQL-скрипт идемпотентный: уже выполненное он пропускает.
